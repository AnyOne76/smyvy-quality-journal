# Смывы — рабочее место службы качества

Версия **1.5.0**

Учёт и аналитика микробиологических смывов (контроль чистоты оборудования на производстве). Заменяет ручной Excel из 13 вкладок единым приложением: ввод, журнал по цехам и живая статистика.

## Состав

| Файл | Назначение |
|---|---|
| **smyvy.html** | Приложение (ввод · журнал · статистика · ИИ · админ-панель). |
| **app_server.py** | Основной локальный/внутренний сервер: вход, роли, сессии, админка, ИИ-прокси, email-уведомления. |
| **Запустить.bat** | Запуск `app_server.py` и открытие приложения в браузере. |
| **server.py** | Заготовка продакшен-сервера (общая БД журнала, импорт истории). См. `README_SERVER.md`. |
| **parser.py** | Разбор исходного Excel в типизированную базу. |
| **refresh_embedded_history.py** | Перенос ручного журнала Excel в `smyvy.html` и в базу `smyvy_app.db`. |
| **.smtp_config.example** | Пример настроек SMTP для уведомлений администраторам. |
| **07. Результаты смывов 2026 (3).xlsx** | Последняя версия ручного журнала, 2538 проб. Из него взята история в версии 1.3. |
| **07. Результаты смывов 2026 (2).xlsx** | Ручной журнал на 6 октября, 2500 проб. |
| **08. Результаты смывов 2026.xlsx** | Первый журнал, до дописки сотрудниками. |

Для работы программы Excel не нужен. Все смывы лежат в базе `smyvy_app.db`. Файлы Excel остаются как источник истории. Если сотрудники снова допишут ручной журнал, свежий файл кладут в папку программы и запускают `python refresh_embedded_history.py`. Скрипт сам берёт самый новый файл.

## Запуск (локально)

Двойной клик по **Запустить.bat** → `http://localhost:8000/input`.

Или вручную:
```
python app_server.py
```

Первый зарегистрированный пользователь становится администратором. Остальным роль назначает админ.

## Учётные записи и роли

- При регистрации сотрудник указывает **email, пароль и ФИО**.
- Роль назначает **администратор** после регистрации.
- Ответственный в новых записях подставляется из учётной записи.
- Роли:
  - `pending` — ожидает назначения роли;
  - `viewer` — только просмотр;
  - `quality` — ввод + редактирование/удаление;
  - `admin` — всё + управление пользователями.

## Email-уведомления

При новой регистрации письмо уходит **всем активным администраторам** (email = логин учётки).

1. Скопируйте `.smtp_config.example` → `.smtp_config`
2. По умолчанию — корпоративный SMTP-релей `10.0.4.70:25` без логина (как validationOnTT / documents_conveyer / hr_passport). При необходимости поправьте `from_email`.
3. Проверка: `python app_server.py testmail`

Файл `.smtp_config` в `.gitignore` — в репозиторий не попадает.

## ИИ-помощник

Прокси к **DeepSeek** (модель `deepseek-chat`) встроен в `app_server.py`.

1. Скопируйте `.ai_key.example` → `.ai_key`
2. Вставьте API-ключ DeepSeek одной строкой ([platform.deepseek.com](https://platform.deepseek.com/api_keys))
3. Перезапустите `Запустить.bat`

Без ключа вкладка ИИ недоступна, остальное работает. Файл `.ai_key` в `.gitignore`.

## Что умеет приложение

- **Ввод** — цех подставляет точки и показатели; проверка норматива сразу.
- **Журнал** — фильтры, поиск, правка/удаление по роли, резервные копии, выгрузка в Excel.
- **Статистика** — KPI, динамика, drill-down, тепловая карта, проблемные точки.
- **Админ** — пользователи, роли, блокировка, след удалённых смывов, удаление и возврат цехов, точек и мастеров в списках ввода.
- **ИИ** — чат по данным, отчёт, рекомендации по несоответствиям. Код ИИ и почты в этом обновлении не менялся.

### Обязательная смена временного пароля

- После того как администратор нажал «Пароль» и выдал временный пароль, сотрудник при входе сразу видит окно «Новый пароль». Он дважды вводит свой пароль, не короче 5 символов, и только потом попадает в программу.

- Смена пароля через значок ключа и команда `python app_server.py setpass` работают как раньше.

Код почты и ИИ в этой версии не менялся.

## Версия 1.3

### Все смывы в одной базе

- Смывы теперь хранятся в базе `smyvy_app.db`, рядом с учётными записями. Это одна база, внутри разные таблицы: пользователи, смывы, удалённые смывы, списки цехов, точек и мастеров.
- При первом запуске версия 1.3 сама переносит в базу смывы, которые сотрудники внесли в версии 1.2. Она берёт их из `backups/smyvy-journal.json` и дневных копий `smyvy-journal-ГГГГ-ММ-ДД.json`. Удалённые смывы при этом не возвращаются. Перенос делается один раз.
- История из ручного журнала тоже лежит в базе. При запуске программа только добавляет пробы, которых в базе ещё нет. Уже лежащие строки она не переписывает.
- Браузер держит у себя только смывы, которые сервер ещё не подтвердил, например если пропала сеть. Как только сервер ответил, браузер отправляет их и очищает свою очередь.
- Если два сотрудника правят один смыв, остаётся более поздняя правка. Браузер со старой копией её не затирает.

### История

- История обновлена из `07. Результаты смывов 2026 (3).xlsx`: 2538 проб. К прежним 2500 добавлены 38: Деликатесный — 15 (10 и 12 октября), Сырьевой — 15 (9 октября), Колбасный — 8 (8 октября). Ни одна прежняя проба не пропала.
- `refresh_embedded_history.py` пишет историю сразу и в `smyvy.html`, и в базу. Смывы, которые сотрудники внесли в программу, скрипт не трогает и ничего из базы не удаляет.

### Скорость

- Журнал открывает первые 80 строк. Кнопка «Показать ещё» добавляет следующие 160. Над таблицей по-прежнему видно, сколько записей всего.
- Статистика, поиск, фильтры и выгрузка в Excel работают по всем записям, а не только по видимым строкам.
- Сервер держит готовый журнал в памяти. Браузер каждые 8 секунд спрашивает, не изменился ли он. Если изменений нет, приходит короткий ответ, и страница ничего не пересчитывает.
- Статистика пересчитывается только после изменения журнала.

### Ежедневная копия

- В 20:00 в папку `backups` сохраняется копия всей базы: `smyvy-app-ГГГГ-ММ-ДД.db`. В ней пользователи, смывы, удалённые смывы и списки. Копия снимается средствами SQLite, поэтому она целая, даже если в эту минуту кто-то вносит смыв.
- Вторую копию можно класть на другой диск или сетевую папку. Для этого в папке программы создать файл `.backup_dir` и записать в него одной строкой путь к папке. Вместо файла можно задать переменную окружения `SMYVY_BACKUP_DIR`. Если вторая папка недоступна, копия в `backups` всё равно сохраняется. Файл `.backup_dir` в GitHub не попадает.
- Если в 20:00 программа была закрыта, копия за этот день делается при следующем запуске.
- Файлы `smyvy-journal*.json` в `backups` по-прежнему пишутся как дополнительная копия. Кнопка «Восстановить» читает их, как и раньше.

Код почты и ИИ в этой версии не менялся.

На странице «Пользователи» блок «Цеха, точки и мастера». Удаление убирает название из списков при новом занесении. Смывы, которые уже есть в журнале, остаются.

### Ежедневные копии

Так было в версиях 1.0–1.2. С версии 1.3 смывы лежат в `smyvy_app.db`, см. раздел «Версия 1.3».

В 20:00 по времени компьютера, на котором запущена программа, в папку `backups` рядом с `app_server.py` сохраняются обе базы. В GitHub эта папка не попадает. Другого места для копии смывов нет.

- `smyvy-journal.json` — общий журнал новых смывов. Его читает программа, поэтому запись одного сотрудника видна остальным. Этот файл не удалять.
- `smyvy-journal-ГГГГ-ММ-ДД.json` — копия того же журнала за день. Файл за день один. Записи с разных компьютеров складываются в него, и в 20:00 эта копия фиксируется.
- `smyvy-app-ГГГГ-ММ-ДД.db` — база пользователей и список удалённых смывов. Тоже пишется в 20:00.

Если в 20:00 программа уже закрыта, файл смывов остаётся в этой папке с последнего сохранения за день, а копия пользователей дописывается при следующем запуске. Кнопки «Копия» и «Восстановить» в журнале остаются. Исторические смывы из Excel живут внутри `smyvy.html` и в эту папку не переносятся.

### Что на сервере не удалять

При обновлении с GitHub оставить на месте:

- `smyvy_app.db` — главная база: учётные записи, все смывы, удалённые смывы, списки цехов, точек и мастеров. Если файл удалить, пропадут логины, пароли и смывы, которые сотрудники внесли в программу.
- `.secret` — ключ входа. Если удалить, всем придётся войти заново.
- `.ai_key` — без него вкладка ИИ не отвечает. Остальное работает.
- `.smtp_config` — письма о регистрации.
- `.backup_dir`, если его создали, — путь ко второй папке копий.
- папку `backups/` — дневные копии базы и файлы `smyvy-journal*.json`, из которых версия 1.3 при первом запуске переносит смывы версии 1.2.

История смывов есть и внутри `smyvy.html`, и в базе: 2538 проб из `07. Результаты смывов 2026 (3).xlsx`.

## Развёртывание на сервере

Рабочий процесс — **`app_server.py`** (не `server.py`). См. **README_SERVER.md** (HTTPS, роли).

На **aidev** (`10.0.5.173:8020`, каталог `/home/devuser/projects/smyvy-quality-journal`) приложение в **Docker** (`docker compose`, `restart: unless-stopped`). Обновление с GitHub — через Actions (см. ниже). Домен **laboratory-washes.kolbasa.ru** → nginx на порт **8020** (пример: `deploy/nginx-laboratory-washes.conf.example`).

### Автообновление с GitHub (CI/CD)

1. **Тесты** — job `test` на каждый push и PR (`pytest`, см. `requirements-test.txt`).
2. **Деплой** — только push в `main`, после зелёного `test` и **Approve** в Environment **`production`** (required reviewers в настройках репозитория).
3. На aidev **self-hosted runner** выполняет [`scripts/deploy.sh`](scripts/deploy.sh): `git merge --ff-only`, pytest, `docker compose up -d --build`.

Локально:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-test.txt
.venv/bin/pytest -q
```

**One-time на aidev:** Docker + `docker compose`, venv с тестами (`requirements-test.txt`), self-hosted runner (`scripts/install-github-runner.sh`). Данные (`*.db`, `.secret`, `.ai_key`, `.smtp_config`, `backups/`) монтируются в контейнер с хоста.

**При деплое не трогаются** (см. список выше): `smyvy_app.db`, `.secret`, `.ai_key`, `.smtp_config`, `.backup_dir`, `backups/`.

**Откат:** `git checkout <коммит>` и `docker compose up -d --build`.
