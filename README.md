# Смывы — рабочее место службы качества

Учёт и аналитика микробиологических смывов (контроль чистоты оборудования на производстве). Заменяет ручной Excel из 13 вкладок единым приложением: ввод, журнал по цехам и живая статистика.

## Состав

| Файл | Назначение |
|---|---|
| **smyvy.html** | Приложение (ввод · журнал · статистика · ИИ · админ-панель). |
| **app_server.py** | Основной локальный/внутренний сервер: вход, роли, сессии, админка, ИИ-прокси, email-уведомления. |
| **Запустить.bat** | Запуск `app_server.py` и открытие приложения в браузере. |
| **server.py** | Заготовка продакшен-сервера (общая БД журнала, импорт истории). См. `README_SERVER.md`. |
| **parser.py** | Разбор исходного Excel в типизированную базу. |
| **refresh_embedded_history.py** | Обновление встроенной истории в `smyvy.html` из Excel. |
| **.smtp_config.example** | Пример настроек SMTP для уведомлений администраторам. |
| **08. Результаты смывов 2026.xlsx** | Исходный журнал смывов. История из него уже встроена в `smyvy.html`. |

## Запуск (локально)

Двойной клик по **Запустить.bat** → `http://localhost:8000/input`.

Или вручную:
```
python app_server.py
```

Первый зарегистрированный пользователь становится администратором. Остальным роль назначает админ.

## Учётные записи и роли

- При регистрации сотрудник указывает **email, пароль и ФИО**.
- Роль назначает **администратор** после регистрации.
- Ответственный в новых записях подставляется из учётной записи.
- Роли:
  - `pending` — ожидает назначения роли;
  - `viewer` — только просмотр;
  - `quality` — ввод + редактирование/удаление;
  - `admin` — всё + управление пользователями.

## Email-уведомления

При новой регистрации письмо уходит **всем активным администраторам** (email = логин учётки).

1. Скопируйте `.smtp_config.example` → `.smtp_config`
2. По умолчанию — корпоративный SMTP-релей `10.0.4.70:25` без логина (как validationOnTT / documents_conveyer / hr_passport). При необходимости поправьте `from_email`.
3. Проверка: `python app_server.py testmail`

Файл `.smtp_config` в `.gitignore` — в репозиторий не попадает.

## ИИ-помощник

Прокси к **DeepSeek** (модель `deepseek-chat`) встроен в `app_server.py`.

1. Скопируйте `.ai_key.example` → `.ai_key`
2. Вставьте API-ключ DeepSeek одной строкой ([platform.deepseek.com](https://platform.deepseek.com/api_keys))
3. Перезапустите `Запустить.bat`

Без ключа вкладка ИИ недоступна, остальное работает. Файл `.ai_key` в `.gitignore`.

## Показатели и нормы

КМАФАнМ (лимит 1×10³ КОЕ/см²), БГКП, Proteus, Salmonella, Listeria, Staph, Плесень, Дрожжи.  
Статусы: **норма** · **повышенный** · **превышение** · **несоответствие**.

## Что умеет приложение

- **Ввод** — цех подставляет точки и показатели; проверка норматива сразу.
- **Журнал** — фильтры, поиск, правка/удаление по роли, резервные копии, выгрузка в Excel.
- **Статистика** — KPI, динамика, drill-down, тепловая карта, проблемные точки.
- **Админ** — пользователи, роли, блокировка, след удалённых смывов, удаление цехов, точек и мастеров из списков ввода.
- **ИИ** — чат по данным, отчёт, рекомендации по несоответствиям. Код ИИ и почты в этом обновлении не менялся.

## Что добавлено в этой версии

Рабочая программа — `app_server.py` и `smyvy.html`. Файл `server.py` по-прежнему черновик, его не запускать.

### Страницы

У каждого раздела свой адрес и заголовок вкладки:

- `/input` — занести смыв
- `/journal` — журнал
- `/statistics` — статистика
- `/ai` — ИИ
- `/users` — пользователи, только администратор

Старые адреса `/vvod`, `/zhurnal`, `/statistika`, `/ii`, `/polzovateli` открываются и сами переходят на новые.

### Журнал и ввод

- История обновлена из `08. Результаты смывов 2026.xlsx`: 2449 проб. Новые листы: «Консервный (Цех №10)» (46 проб), «ТО (цех №6)» и «СГП» (в файле листы есть, строк со смывами нет). Прежние цеха остались на своих местах, чтобы уже внесённые смывы не привязались к другому цеху.
- В журнале видны все записи, не только первые 300.
- Карандаш у новой записи редактирует показатели. В колонке «Ответственный» видны все изменения последней правки.
- Поле «Мастер цеха» общее для всех цехов: нового мастера можно добавить и потом выбрать снова. Оно не зависит от цеха и точки отбора. В выгрузке Excel колонка называется «Мастер цеха», а бывшая колонка «Мастер» называется «Ответственный».
- Новый цех в выгрузке Excel встаёт последним листом.
- Роль «Мастер» убрана. Удалять смывы могут служба качества и администратор.
- Удаление смыва сначала записывается на сервере: какой смыв, дата, кто и когда. Список виден только администратору на странице «Пользователи». Вернуть строку в журнал оттуда нельзя. Человеку, который удалил смыв, об этом списке не сообщается.
- Окно «Повторные нарушители» открывает историю выбранной точки. «Соответствие 100%» означает, что нарушений не было. Повышенный КМАФАнМ ниже лимита 1 000 КОЕ в несоответствия не входит.

### Только администратор

На странице «Пользователи» блок «Цеха, точки и мастера». Удаление убирает название из списков при новом занесении. Смывы, которые уже есть в журнале, остаются.

### Ежедневные копии

В 20:00 по времени компьютера, на котором запущена программа, в папку `backups` рядом с `app_server.py` сохраняются обе базы. В GitHub эта папка не попадает. Другого места для копии смывов нет.

- `smyvy-journal-ГГГГ-ММ-ДД.json` — база смывов: внесённые смывы, цеха, точки и мастера. Файл за день один. Записи с разных компьютеров складываются в него в течение дня, и в 20:00 эта копия фиксируется.
- `smyvy-app-ГГГГ-ММ-ДД.db` — база пользователей и список удалённых смывов. Тоже пишется в 20:00.

Если в 20:00 программа уже закрыта, файл смывов остаётся в этой папке с последнего сохранения за день, а копия пользователей дописывается при следующем запуске. Кнопки «Копия» и «Восстановить» в журнале остаются. Исторические смывы из Excel живут внутри `smyvy.html` и в эту папку не переносятся.

### Что на сервере не удалять

При обновлении с GitHub оставить на месте:

- `smyvy_app.db` — учётные записи. В новом Excel пользователей нет. Если файл удалить, логины и пароли пропадут.
- `.ai_key` — без него вкладка ИИ не отвечает. Остальное работает.
- `.smtp_config` — письма о регистрации.
- папку `backups/`, если она уже есть.

Смывы из файла 08 подставятся сами: они уже внутри `smyvy.html`.

## Развёртывание на сервере

Обновить файлы программы с GitHub и перезапустить `python app_server.py`. См. также **README_SERVER.md** (`server.py`, HTTPS, роли). Рабочий запуск — `app_server.py`, не `server.py`.
