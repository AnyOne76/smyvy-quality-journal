# Смывы — развёртывание на сервере (безопасность и надёжность)

Заготовка серверной части: `server.py`. Минимум зависимостей (стандартная библиотека Python + SQLite; `pandas`/`openpyxl` нужны только для разового импорта истории).

---

## Что уже заложено

| Область | Реализовано |
|---|---|
| **Аутентификация** | логин + пароль, хеш **PBKDF2-SHA256** с солью (240k итераций) |
| **Роли** | `viewer` (чтение) · `master` (ввод) · `quality` (ввод/правка/удаление) · `admin` |
| **Сессии** | подписанная HMAC-cookie, `HttpOnly`, `SameSite=Strict`, срок 12 ч |
| **Аудит** | таблица `audit`: вход, добавление, правка, удаление — кто, что, когда |
| **Валидация** | проверка цеха, точки, даты, показателей на сервере |
| **Заголовки** | `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` |
| **Хранилище** | SQLite (один файл — легко бэкапить); заменяется на PostgreSQL |

## Быстрый старт

```bash
# 1. создать базу, импортировать историю из Excel, создать admin
python server.py init
#    → выведет временный пароль admin — запишите и смените после входа

# 2. добавить пользователей (мастера, службу качества, руководителя)
python server.py adduser

# 3. запустить
python server.py run          # http://127.0.0.1:8000
```

Роли при создании: `viewer`, `master`, `quality`, `admin`.

## Обязательный чек-лист перед продакшеном

### Безопасность
- [ ] **Смените пароль admin** сразу после первого входа.
- [ ] Файл **`.secret`** (ключ подписи сессий) — не удалять, не публиковать, права `600`. При его утечке — все сессии скомпрометированы.
- [ ] **HTTPS обязателен.** `server.py` слушает `127.0.0.1` — наружу его выставляют **только через обратный прокси с TLS** (nginx / Caddy). Пример Caddy:
  ```
  smyvy.ваш-домен.local {
      reverse_proxy 127.0.0.1:8000
  }
  ```
  Caddy сам получит/обновит сертификат. Без HTTPS пароли идут открытым текстом — недопустимо.
- [ ] Сервер — **во внутренней сети предприятия**, не в публичном интернете.
- [ ] Cookie сессии уже `HttpOnly`/`SameSite=Strict`; за HTTPS добавьте флаг `Secure` (одна строка в `_login`).
- [ ] Минимум прав: рядовым мастерам — роль `master`, правка/удаление — только `quality`.

### Надёжность
- [ ] **Резервное копирование БД** по расписанию. SQLite — это один файл:
  ```bash
  # ежедневно, с датой в имени
  sqlite3 smyvy_prod.db ".backup 'backup/smyvy_$(date +%F).db'"
  ```
  Настройте cron / «Планировщик задач Windows». Храните копии на другом диске/сервере.
- [ ] Включите **WAL-режим** для устойчивости при сбоях:
  `sqlite3 smyvy_prod.db "PRAGMA journal_mode=WAL;"`
- [ ] Проверьте **восстановление** из копии (реальная проверка, не «на бумаге»).
- [ ] Автозапуск сервиса при перезагрузке (systemd на Linux / служба или «Планировщик» на Windows), чтобы сервер не зависел от сеанса пользователя.
- [ ] Логи запросов — подключите при необходимости (сейчас отключены для тишины: метод `log_message`).

### Масштаб (когда данных станет много)
- [ ] Переход на **PostgreSQL**: заменить слой `db()` и SQL-плейсхолдеры (`?` → `%s`). Схема таблиц та же.
- [ ] Индексы `ix_probes_ceh`, `ix_probes_date` уже созданы.

## Что осталось доделать (интеграция фронтенда)

Сейчас `smyvy.html` хранит новые записи в браузере (localStorage). Для серверной версии фронтенд нужно переключить на API:

| Действие в интерфейсе | Запрос к серверу |
|---|---|
| Загрузка журнала | `GET /api/probes` |
| Добавить запись | `POST /api/probes` |
| Изменить запись | `PUT /api/probes/{id}` |
| Удалить запись | `DELETE /api/probes/{id}` |
| Вход | `POST /api/login` |
| Кто я / выход | `GET /api/me` · `POST /api/logout` |

Это отдельный, понятный шаг: заменить чтение/запись `localStorage` на вызовы `fetch(...)`. Историческая выборка перестанет «зашиваться» в HTML — данные будут приходить только после входа. Логика статистики и Excel-выгрузки остаётся прежней.

## Быстрая проверка (curl)

```bash
curl -c ck -X POST localhost:8000/api/login -H "Content-Type: application/json" \
  -d '{"login":"admin","password":"..."}'
curl -b ck localhost:8000/api/probes
```

Проверено локально: импорт 1859 проб, вход, отказ прав для `viewer` (403), 401 без входа и на неверный пароль, 422 на неверный ввод, запись аудита — работают.
